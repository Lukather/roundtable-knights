## Design Specificity Verdict

**LLM assessment:** Partially authored, partially interchangeable. The Council Chamber token system is genuinely specific: the void-dark palette, the 3px persona-color left border on TurnBubble, the avatar ring system, and the fade-in-up entrance create real product character. These choices read "deliberate simulation tool."

However, three patterns betray category-interchangeable thinking: (1) The HeroPreview window chrome (macOS traffic-light dots) communicates "we have a desktop app" rather than anything about debating personas. (2) The AUDIENCES section uses `#10b981` (green) and `#f59e0b` (amber) as structural accent colors — the same values already used as semantic status colors in STATUS_MAP, creating an unintentional semantic collision. (3) The sword emoji is the only medieval register in the product; "Roundtable Knights" makes a character promise the visual language hasn't decided to keep.

**Deterministic scan — 14 findings, 5 notable:**
- `bounce-easing` (warning): `animate-bounce` used for thinking-indicator dots in `page.tsx:109` and `DiscussionFeed.tsx:66` — design slop pattern, explicitly not "precise and quiet."
- `side-tab` (warning): `border-l-4` in `page.tsx:308` (audience cards) and `ReportView.tsx:81/102` are thicker than the 3px persona-border maximum.
- `design-system-color` (advisory): `AttachmentsPanel.tsx:29/48` uses `#8b5cf6` and `#2563eb` — neither is in the token set.
- `design-system-font-size` (advisory): `text-[10px]` in `TurnBubble.tsx:76/90` — below the type ramp floor.
- `design-system-color` — DEMO_TURNS persona colors: false positive (demo data only).

**False positives:** `border-radius: 2px/3px` advisories (scrollbar, inline code) are micro-utility shapes. Demo persona hex values are not live tokens. The `border-l-2` side-tab warning on TurnBubble is intentional product language.

## Overall Impression

The product has a real visual identity — the Council Chamber palette and the persona-color turn-bubble system are distinctive and earned. But the score lands at 19/40 because the two most important UX surfaces (setup form and error recovery) are essentially unbuilt from a quality standpoint. The setup form is a cognitive cliff between the user and the product's peak moment. Errors leave users stranded. And a contrast failure on `--muted` means secondary text fails WCAG AA at every normal text size across every component.

**The single biggest opportunity:** turning the setup form into a 3-step guided flow that builds momentum toward "Start."

## What's Working

**1. TurnBubble persona color system**
The 3px border-left + avatar ring + role chip in the same persona color creates a scannable identity lane. Users track who said what by color alone at reading speed. The interjection variant (−mt-2, pl-6, 2px border) correctly reduces visual weight without breaking color identity. This is product-specific design.

**2. Token architecture in globals.css**
Two complete theme sets, a single accent color, three named surface steps, muted/foreground separation. The light theme has its own values. This is the kind of system that scales without visual debt accumulating.

**3. STATUS_MAP as a typed visual contract**
A `Record<string, {label, color, bg}>` means every status badge renders consistently. The rgba-at-0.1-opacity badge background is a clean pattern that prevents status color proliferation.

## Priority Issues

### [P0] No error recovery surface
**What:** STATUS_MAP.error renders a red badge. No message, no retry, no failure cause, no distinction between transient and config errors.
**Why it matters:** AI runs fail. When they do, the user has invested setup time. A red dot as the entire recovery UX creates abandonment. The last meeting in the recent list with an error badge is a sour last impression — violating the peak-end rule's end component.
**Fix:** Add `errorMessage: string | null` to the Meeting type. Render the message below the badge. Add a "Retry" button. Distinguish "API timeout → Retry" from "Invalid config → Edit."
**Suggested command:** `/impeccable harden`

### [P1] MeetingSetupForm is a cognitive cliff
**What:** All setup fields (title, topic, context, turn slider, persona selection, speaking order, attachments) rendered as a single unbroken scroll with no section grouping, no progressive disclosure, no stepper, no back/cancel.
**Why it matters:** The setup form is the last thing between the user and the product's value. Overload here directly suppresses meetings run.
**Fix:** 3 steps: (1) What — topic + context, (2) Who — persona selection, (3) Options — turns, order (collapsed), attachments (collapsed). Back button on steps 2-3. Summary confirmation screen before submit.
**Suggested command:** `/impeccable shape meeting-setup`

### [P1] Avatar color system split between two strategies
**What:** PersonaCard uses `avatarColor(persona.id)` → Tailwind class. TurnBubble uses `style={{ color: persona.color }}` → inline hex. The same persona's avatar color may differ between the card view and the debate view.
**Why it matters:** The persona color is the primary identity signal in the debate view. Inconsistency breaks recognition and undermines the strongest design element in the product.
**Fix:** Normalize to hex everywhere. Remove the Tailwind avatar class approach. Single utility function derives avatar background from stored hex.
**Suggested command:** `/impeccable polish`

### [P2] `--muted` contrast fails WCAG AA at normal text sizes
**What:** `#6b6b80` on `#0f0f14` ≈ 4.0:1. Light theme `#8888a8` on `#f7f7fb` ≈ 4.35:1. Both below the 4.5:1 AA threshold. Used pervasively for secondary text, labels, metadata, and placeholder copy.
**Fix:** Dark: shift to `#7a7a92` (≈4.6:1). Light: shift to `#7070a0` (≈4.7:1). Small adjustments; visual character maintained.
**Suggested command:** `/impeccable audit`

### [P2] `animate-bounce` on thinking indicator is design slop
**What:** Thinking-indicator dots in DiscussionFeed.tsx:66 and HeroPreview use `animate-bounce`. The detector flagged it correctly — it's the most overused animation in frontend UI, applies spring easing that feels toylike, and contradicts the "precise and quiet" design spec.
**Why it matters:** The thinking indicator is the product's liminal moment — a persona formulating a thought. This is character-defining. Bounce feels like a loading spinner.
**Fix:** Replace with staggered opacity fade: `animation-delay: 0ms / 150ms / 300ms`, slow `ease-in-out` cycle. Dots appear and fade in sequence. Consistent with the `fade-in-up 220ms ease-out` motion vocabulary.
**Suggested command:** `/impeccable animate`

## Persona Red Flags

### Alex (Power User) — running a second meeting with a modified cast
- No "Clone meeting" on the recent meetings list. Must rebuild setup from scratch.
- Speaking order reorder uses up/down buttons only — up to 28 clicks to reorder 8 personas. No drag-and-drop.
- No keyboard shortcut to submit the form or navigate steps.
- No persona-set templates for reuse across meetings.
- Turn count slider has no adjacent numeric input for precision keying.

### Jordan (First-Timer) — creating first persona and running first meeting
- "Speaking order" section appears before Jordan understands what speaking order means. No tooltip or explanation.
- No inline explanation of Topic vs Context textareas — Jordan will put content in the wrong field.
- After submitting, no progress signal during the AI run. Jordan will not know if anything is happening.
- The sword emoji branding and "Roundtable Knights" name give no immediate hint this is an AI deliberation tool.
- No visible link to personas page from setup when the persona grid is empty except small inline text.

### Sam (Accessibility-Dependent) — reviewing a completed meeting report
- MeetingSetupForm.tsx:180-181: Up/down reorder buttons use bare ↑ ↓ characters with no `aria-label`. Screen reader announces "up arrow button" with no context.
- PersonaCard hover uses `active:scale-[0.99]` but no focus-visible override. Keyboard focus on the card is visually ambiguous.
- Avatar colors from the Tailwind rotation are not contrast-checked against white initials. Some colors in the rotation may fail.
- STATUS_MAP uses color as the primary status signal; 12px label text may be missed by low-vision users.

## Minor Observations

- `AttachmentsPanel.tsx:29/48` uses `#8b5cf6` and `#2563eb` — not in the token set. Use `var(--accent)` or a semantic status token.
- `ReportView.tsx:81/102` and `page.tsx:308` use `border-l-4`. The established maximum per DESIGN.md is 3px on turn bubbles. Bring to 3px or convert to a different device.
- Navigation has no "Meetings" link. The only access to meeting history is the homepage bottom section — inaccessible from the meeting detail view.
- ThemeToggle component is icon-only in the nav. If it has no `aria-label`, it fails for keyboard/screen reader users.
- `MODERATOR_COLOR = '#f59e0b'` is a magic constant. Should be a CSS variable.
- `formatDate` hardcodes `en-US` locale. Acceptable for a local tool.
